## 1. SIM-429 — the walk surplus (fix FIRST; most of SIM-514 hangs off it)

**The defect.** The sim issues +11.7% walks. SIM-509 already removed the fake-walk
half (HBP mislabeled as balls); what remains is real: the pitch mix is ball-heavy.
Walks compound — a small per-count ball surplus multiplies across the pitches of a
plate appearance. Two follow-ons wait on this fix: the K prop to bet-grade
(ECE 0.109 → <0.10) and the CLV re-measure (the old ~49% beat-close read predates
the rebuild and is not evidence).

**The proposed diagnosis (one instrumented script, hundreds of games).**
Build `scripts/sim429_count_diagnosis.py` that reports, side by side:

1. **Per-count outcome rates, sim vs the pool's own.** For each of the 12
   ball-strike counts: P(ball / called_strike / swinging_strike / foul / in_play /
   hit_by_pitch). The sim side: instrument `StateMachine.step_pitch` outcomes per
   live count over ≥400×≥20 games. The pool side: `sim.pitch_pool` grouped by
   (count_balls, count_strikes) — the count buckets the draw already uses
   (`FullPoolSampler._pool_meta` `bucket_rows`; the SIM-429 count-bucket CDFs).
2. **Count-visitation distribution, sim vs MLB** (pitches seen per count per PA).
3. **Walk rate per count-path** (how often a PA passing through 2-0/3-1 walks).

**The decision tree the numbers feed:**
* **Per-count rates DIVERGE from the pool's own** → the draw's weighting tilts
  ball-heavy inside a count. Suspects, in order: the batter-affinity kernel
  (walk-heavy batters over-weighted), the pitcher-similarity factor, the
  situation kernel, recency. Fix the kernel bandwidth or the factor — this is
  SIM-476 temperature-fit territory, done per factor with an ablation seam
  (clone the `SIM_STEAL_ABLATE_*` pattern).
* **Per-count rates MATCH the pool but visitation is off** → the defect is in
  count TRANSITIONS: foul handling, two-strike swing rates, the count machine's
  terminal handling. Fix the specific transition cell.
* **Both match and BB is still high** → the pool's own era (2024-26) walks more
  than the 2025 band centre — a reference question for the OWNER, the SIM-507
  precedent (pre-register the era decomposition before claiming it).

**After the fix lands:** all-seasons pool rebuild is NOT needed unless the pool
CASE changes (a kernel fix is code-only). Re-run the 12×471 lane; expect DP/K/SB
to move WITH the walk fix (see SIM-514). Then `make calibrate` +
`make validate-props` for the K prop, then `scripts/clv_backtest.py` re-measure.

## 2. SIM-514 — the four post-transition reads (diagnosis only; likely 3 of 4 close with SIM-429)

Run ONE instrumented lane-style batch (≥400×≥20, production flags) that reports
the four decompositions. Do not tune anything on a per-game read.

* **(a) DP +8.3% — decompose per opportunity.** Opportunity = a ball-in-play
  resolution with a runner on 1B and <2 outs. Report sim DP-per-opportunity vs
  the pool's own per-cell DP rate (the transition rows carry it exactly:
  `runner_1b_dest = 0` + `batter_dest = 0` on GIDP events). **Hypothesis: the BB
  surplus inflates runner-on-1B occupancy; per-opportunity matches and the row
  closes with SIM-429.** If per-opportunity is ALSO high, compare the drawn event
  mix per cell vs the pool's own per-cell mix (the batter kernel may over-weight
  ground-ball hitters in occupied cells).
* **(b) K -2.5% — decompose K/PA vs PA/game.** More real DPs end innings sooner,
  so games have fewer PAs. If K per PA is green, there is NO strikeout defect —
  the row closes with a note. (The channel is floor-driven: half-width 0.1105.)
* **(c) SB -7.6% — decompose attempts per opportunity-pitch vs opportunities per
  game.** Use the SIM-468 denominator (the steal probes exist in the acceptance
  conftest). **Hypothesis: the phantom-DP era left doubled-off runners STANDING
  on base and those ghost runners stole (SB read +5.7% HIGH pre-epic); correct
  removal cut opportunities.** Expect attempts-per-opportunity to still match the
  certified 0.748-vs-0.76 read. Opportunities per game should normalize once BB
  does.
* **(d) 3B +11.9% — NOT traffic (+0.015/tg absolute; fewer PAs should deflate
  it, yet it rose).** Two checks: (1) the drawn triple rate per base-out cell vs
  the pool's OWN per-cell rate — if they match, the surplus is the pool's 2024-26
  era mix vs the 2025 centre, and the fix is an OWNER decision on the band
  reference (the SIM-507 precedent), not code; (2) verify no double-count between
  drawn `triple` rows and the S5 batter-stretch draw (`5_0_3`) — the stretch must
  never relabel a double's event, and a drawn triple must never also fire a
  stretch draw (`_run_advancement_draws` gates on `hit == 2`; confirm).

## 3. SIM-491 — rebuild the three inert nudges as draw weights (AFTER SIM-429/514)

**The defect.** Home-field (SIM-412), park (SIM-411) and fielder-quality
(SIM-425b) worked by FLIPPING the drawn event post-draw. On the transition
architecture a flip contradicts the drawn row's own movement, so all three are
INERT on the production path (documented in `_full_pool_fielding` /
`_resolve_in_play`). home_win_pct reads 0.4735. The old flip code still exists on
the legacy-bundle path only.

**The rebuild pattern is the same for all three: move the effect INTO the fielding
draw's weights, so it emerges from real rows.** The mechanism to clone is the
SIM-413 platoon reweight (a soft per-row multiplier in `battedball_new_pa`) and
the SIM-512 arm factor (`_steal_actor_factor` over an embedding).

* **SIM-412 home-field:** the pool does NOT yet carry the batting side. (1) Add
  `bat_home BOOLEAN` to `sim.outcome_pool` — from `raw.pitches` (the top/bottom
  half names the batting side) — as DuckDB migration 0019 (v18→v19; columns LAST,
  the positional-INSERT trap; bump the version file + the `test_sim_store`
  version test; `POOL_BUILDER_VERSION` → sim491.1). (2) Export it into the bb
  meta parquet (the `_bb_take` optional-column pattern). (3) In
  `battedball_new_pa`, softly up-weight rows whose `bat_home` matches the live
  batting side (a `home_off_weight` <1 on mismatched rows — the exact
  `platoon_off_weight` shape). Home advantage then appears at the pool's real
  rates. (4) Certify: home_win_pct needs 13,365 decisive games (~8-16 h) —
  its OWN lane, not the 12×471.
* **SIM-411 park:** `venue_id` is ALREADY on every pool row and in the bb meta.
  Soft-kernel each row by |park_run_factor(live venue) − park_run_factor(row
  venue)| using `derived.park_factors` (season, `factor_type='R'`,
  `regressed_factor`) — a Gaussian on the factor delta, bandwidth a SIM-476 fit
  target. Delete the post-draw flip when this lands.
* **SIM-425b fielder quality:** the pool rows carry `fielder_id`/`fielder_pos`
  and the fielder embedding carries OAA + arm features. Weight rows by similarity
  between the LIVE defender at the row's position (defense map —
  `_live_fielder_at_drawn_position` already resolves it) and the ROW's fielder —
  exactly the `_FIELDER_ADV_FEATURES` factor the advancement draw uses, with an
  OAA-centred feature set. A good live shortstop then pulls the draw toward rows
  where good shortstops made plays.

**Validation protocol (the ticket's own bar):** one flag at a time, ≥400 sims ×
≥20 games, byte-identical with the flag off; then the 12×471 lane with all flags
on; home_win_pct's full-power lane last. Re-check the CS/3B/ROE overdispersion
(sim sd > sd_ref) after the rebuilds — it survived the mechanics fix and is still
unexplained.
