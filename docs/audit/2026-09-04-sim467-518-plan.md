# SIM-467 + SIM-518 — the play-picker plan: the cell index and the conditioning epic (2026-09-04)

**Owner summary.** The play picker is the code that chooses each pitch and each
batted ball by scoring a pool of real plays and drawing one by similarity. Two
tickets change it. **SIM-467** makes every draw scan only the plays that match
the live situation instead of the whole pool. That removes the biggest per-play
cost and owns the 30-second target for a 100-game simulation. **SIM-518** adds
the facts the draw cannot see today (the batting side, pitcher fatigue, the
pitch that produced a batted ball) as new pool columns and new draw weights,
under one shared pool rebuild. This plan sequences both so that each part lands
alone, each part is byte-identical when its switch is off, and every switch
flips on only after the certifying lane passes.

**Read first:** `BACKLOG.md` (rows SIM-467, SIM-518, SIM-461/463/464/465/469/472/475/451),
`docs/audit/2026-08-10-sim-loop-remediation-decisions.md` (#19 — the owner's
decision on the cell index and its thin-cell widening), the SIM-517 plan
(`docs/audit/2026-09-03-sim517-plan.md`) for the standing
column → artifact → gated weight → fit → lane pattern, and the SIM-476 fit plan
for the conditional-frequency fit method.

---

## 1. The governing rules (do not relitigate)

1. **The architecture rule, both clauses.** Every decision is a
   similarity-weighted draw from a hard-filtered pool, never a formula. The
   drawn row IS the play. Every factor is a draw WEIGHT or OFF until its weight
   lands. A hard filter is a weight of exactly zero outside the cell; it stays
   OFF (an env switch) until the lane certifies it.
2. **The grade is POOL TOTALS.** The 16 pool bands in `tests/acceptance/bands.py`
   plus the game-graded R and `home_win_pct` are the pass/fail instrument. A
   knob whose channel is green is not a fit target.
3. **The pool window is W1** (full 2023-2026, `RECENCY_FLOOR_SEASONS = 4`).
   Cell thickness comes from SIM-467's widening and SIM-461, never from more
   seasons.
4. **Decision #19 (2026-08-10) rules the thin cells:** a minimum cell size,
   widening in a FIXED order (score band first, then home-or-away, then the
   count), every widening logged. This differs on purpose from the SIM-511
   fielding cell, which never widens: that cell has 24 members, this one has
   2,880.
5. **The SIM-476/517 normalization lesson.** A weight that rides on a hard
   partition is normalized to a mean of 1 inside that partition, so it shifts
   WHICH row is drawn, never the partition's mass.
6. **Measure before building.** The last two perf tickets (SIM-430, SIM-436)
   each found the real cost somewhere other than the filed suspect.

## 2. What exists today (the starting state)

**The pitch draw** (`simulation/full_pool_sampler.py`, `simulation/sim_loop.py:_full_pool_outcome`):

* `new_half_inning` builds `base = f_pitcher · recency` over the WHOLE per-hand
  pitch pool (~1.24M rows L, ~1.53M rows R on the W1 window). Cached per
  (pitcher, hand, season, catcher) — SIM-455 lifetime 1.
* `new_plate_appearance` builds `w = base · f_batter · f_situation_baseout
  [· f_catcher_receiving]` over the WHOLE pool, then splits it into the 12
  count buckets and takes 12 cumulative sums. Cached per (batter, season,
  base-out) — SIM-455 lifetimes 2+3, so a steal or a wild pitch inside a
  plate appearance rebuilds it.
* `draw(balls, strikes)` does one binary search inside the live count's
  bucket. This is already cheap.
* `_pool_meta` holds the 12-bucket row index (`bucket_rows`) and the
  contiguous base-out columns. This 12-cell index IS the mechanism SIM-467
  generalizes.
* The situation factor is a Gaussian over (outs, runners bitmask, inning,
  score_diff) with `sit_sigma = 2.0`. The 2026-07-23 audit (SIT-GEOM) measured
  that at this bandwidth a runner on second retains 0.92 of the empty-bases
  weight: base-out conditioning is close to noise today. The hard cell turns
  it on. Expect the run environment to notice.
* SIM-517 already stores the drawn pitch row (`_pp_last_i`). SIM-472's stated
  precondition ("the pitch draw must expose its row") is met.

**The batted-ball draw** (`battedball_new_pa` / `battedball_draw`): already a
hard base-out cell (24 cells, SIM-511) with soft kernels for the count, inning,
score, platoon, park, home side and the live fielders. It reads three geometry
columns (EV, LA, spray). The outcome pool holds the ten pitch-feature columns
and `pitcher_id`; the artifact exports none of them (SIM-463).

**The steal draw** (`steal_draw`): a hard (target, outs, balls, strikes) cell
over `sim.steal_opportunity_pool`, three actor kernels, run on EVERY pitch with a
stealable lead runner. Roughly 66k rows per cell. It is the next-largest
per-pitch cost after the pitch-weight assembly and SIM-467 does not touch it.

### 5.1 The design

**The cell.** One row's cell is (runners_state 8) × (outs 3) × (count 12) ×
(score band 5) × (batting side 2) = 2,880 cells, exactly the SIM-451
definition. The pitch pool has no batting-side column until phase 2, so stage 1
collapses that dimension: 1,440 cells. The code reads `pool.bat_home is None`
and sets the home dimension's size to 1; nothing else changes at stage 2.

**Two levels, matching the two cache lifetimes.** The plate-appearance cell
(runners, outs, band, side) = 240 cells (120 at stage 1) is fixed for a PA. The
count changes per pitch. So the index orders rows by (PA cell, count bucket):
each PA cell is one contiguous slice, and its 12 count sub-cells are contiguous
inside it. `new_plate_appearance` selects the PA cell's slice and builds 12
cumulative sums over its sub-cells — the SAME structure `bucket_rows` has
today, restricted to the cell. `draw` is unchanged.

**The weights inside the cell are today's weights, bit for bit.** Keep the
existing 4-dimension situation kernel over `sit_baseout[rows]`: the outs and
runners terms are zero inside the cell, so the value on an in-cell row equals
today's value exactly. The ONLY change the switch makes is a weight of zero
outside the cell. This keeps the certified `sit_sigma` untouched (SIM-476 says
do not move it) and makes the A/B interpretable: any frequency move is the
hard filter, nothing else.

**The score band.** `SCORE_BAND_EDGES = (-3, -1, 0, 2)` over the ±5 clamp the
loop already applies — the SIM-451 definition. Move the cell algebra
(`score_band`, `count_bucket`, `cell_key`, `decode_cell`, the `N_*` constants,
the edges) out of `scripts/measure_filter_cells.py` into a new
`simulation/filter_cells.py`, and make the script import it. One definition;
the script's own docstring demands this. `scripts/` is not mounted in the
container, so the sampler cannot import from it.

**Thin cells: decision #19's ladder, precomputed.** Occupancy is a property of
the pool, not of the live state, so the widened row set of every (PA cell,
count) sub-cell is computed once per hand at index-build time:

| Level | Rows used when the sub-cell is short | Cell count |
|---|---|---|
| 0 | the sub-cell itself | 2,880 |
| 1 | the same (runners, outs, side, count), all five bands | 576 |
| 2 | the same (runners, outs, count), both sides | 288 |
| 3 | the same (runners, outs), all counts | 24 |

A sub-cell with fewer than `MIN_CELL` rows steps to the next level until it
has enough. Level 3 is the last resort and never fires on the W1 window (the
base-out cells hold tens of thousands of rows). The sampler counts draws by
level; the lane reports the share of DRAWS at each level (not the share of
cells — the thin cells are rare situations that carry little play mass).

**MIN_CELL.** Re-run `scripts/measure_filter_cells.py` on the live DB for the
W1 window. The script now carries a three-way `coverage_ok` gate and a non-zero
exit (`scripts/measure_filter_cells.py:1014-1073, 1413-1418`) — confirm that
against the SIM-451 row's "NOT TRUSTED" note and close SIM-451 if the second
round landed. Choose `MIN_CELL` from the per-hand percentiles and the
draw-weighted widening share. Starting arm: 20 (about the p10 cell on the W1
window). The default lives in `filter_cells.py`; `SIM_PITCH_MIN_CELL` overrides
it for the ladder runs.

**The receiving factor's normalization group stays the whole-pool count
bucket** at stage 1. The factor is a cached per-(hand, catcher) vector; the
cell path gathers it by row. If the lane's two SIM-517 bands move, the group
becomes (PA cell, count) — decision point 4.

**Where the index is built.** Lazily in `_pool_meta`, per worker: one stable
argsort over N plus an offsets array. ~0.2 s per hand, once, inside the
pre-warm. The index is ~N int32 plus 2,881 offsets — a few megabytes. Publish
it through the SIM-403b shared views only if the pre-warm time shows it.

### 5.3 The tests (unit, synthetic bundle, the `test_full_pool_sampler_sim430.py` fixture pattern)

1. Switch off: the drawn outcome sequence is byte-identical to the pre-change
   sampler at the same seed.
2. Switch on, `MIN_CELL = 0`: the set of rows with non-zero weight equals the
   live cell exactly, and each in-cell weight equals the switch-off weight for
   that row bit for bit.
3. The ladder: a sub-cell below `MIN_CELL` uses level 1; still below, level 2;
   the counter records the level; level order is band → side → count.
4. `bat_home is None` → 1,440 cells; present → 2,880; the same rows land in the
   same cell either way once the side is known.
5. A mid-PA base-out change (a steal) re-selects the cell (the SIM-455 key
   test, extended).
6. The algebra module round-trips with the script (`cell_key` ∘ `decode_cell`
   is the identity over all 2,880 ids; the script's names resolve to the
   module's objects).
7. An empty level-3 cell raises (a data defect, the SIM-511 wording).

### 5.4 Verify and certify

1. `scripts/sim_stats.py --iters 100` on one game, switch off then on: seconds

### 6.1 Scope ruling to confirm (decision point 2)

for the W1 seasons plus an artifact re-export — the SIM-517 part-B shape,

### 6.3 The builder (`_build_pitch_pool`, `POOL_BUILDER_VERSION = "sim518.1"`)

* `bat_home`: `inning_topbot = 'Bot'` (the 0019 definition, reused).
* `pitcher_pitch_count`: pitches this pitcher threw in this game BEFORE this
  pitch — `ROW_NUMBER() OVER (PARTITION BY game_pk, pitcher ORDER BY
  at_bat_number, pitch_number) - 1`. "Before" matches the live
  `state.pitcher_pitch_count` at draw time; a unit test pins the live-side
  read against this convention (the loop increments the count at
  `sim_loop.py:1241`; confirm whether that runs before or after the draw and
  pin the matching definition).
* `times_through_order`: `FLOOR((DENSE_RANK() OVER (PARTITION BY game_pk,
  pitcher ORDER BY at_bat_number) - 1) / 9) + 1` — batters faced before this
  PA, in ninths, plus one. This is exactly the live helper
  `times_through_order(state.pitcher_bf[pitcher])` (`sim_loop.py:426`). One
  definition, both sides; a test runs both on a synthetic game.
* The prev-pitch LAG window stays; the new window functions add one partition
  by (game_pk, pitcher).

### 6.4 The artifact (`pipeline/batch/engine_artifacts.py`)

* Pitch-pool meta parquet: `bat_home` (int8), `pitcher_pitch_count` (int16),

  pattern. `HandPool` gains the three optional fields; they join
  `_HAND_POOL_SHAREABLE_ATTRS`; the loader reads them from the shared views or

* Batted-ball pool: a new `{hand}.pgeom.npy` (N × 10 float32, the `_GEOM_COLS`

  bundle's row order).

### 8.1 SIM-472 — pitch similarity as a primary weight on the fielding draw (ML Engineer)

* **What.** The batted-ball draw currently ignores which pitch was hit. The
  drawn pitch row (`_pp_last_i`) has ten geometry values; each outcome-pool row
  has the same ten (phase 2). A Gaussian over the z-scored 10-dimension
  distance, `bb_pitch_sigma` (`SIM_BB_PITCH_SIGMA`, 0.0 = off exactly), applied
  inside the SIM-511 base-out cell (~25k rows, so the cost is small).
* **Code.** `FullPoolSampler.last_pitch_geom()` (the drawn row's geometry, None
  after an empty-bucket fallback); `battedball_new_pa(..., pitch_geom=...)`;
  the kernel z-scores by the manifest's mean/std; a row with any NaN geometry
  is exactly neutral. `_full_pool_fielding` passes the geometry. Optional
  part B, fitted separately: a pitcher-similarity factor on the fielding draw
  via the dense `pitcher_sim_matrix` gathered on the cell rows (the ticket's
  "pitcher residual"), `SIM_BB_PITCHER_SIGMA`.
* **Fit.** The probe conditions on the drawn pitch's velocity tercile and its
  plate-location zone: the sim's BIP outcome mix (single/double/triple/HR/out,
  and EV/LA) per tier versus the pool's own conditional mix. No normalization:
  the kernel is meant to move the outcome mix per pitch; the pool bands
  (SINGLES_BIP … HR_BIP, DP_OPP) catch any global drift.
* **Rejected alternative, recorded.** Reusing the drawn pitch row itself as the
  batted ball (it is an outcome-pool row) has the pitch and the contact agree
  by construction, but it forgoes the fielder, park and side kernels and draws
  from ~70 in-play rows per count sub-cell. The two-draw design with the kernel
  keeps both.

### 8.2 SIM-465 — the fatigue weight on the pitch draw

* **What.** `f_fatigue` = a Gaussian on |live pitch count − row pitch count|
  (`SIM_FATIGUE_PC_SIGMA`) times a Gaussian on |live TTO − row TTO|
  (`SIM_FATIGUE_TTO_SIGMA`); either 0.0 removes that term; both 0.0 = off
  exactly. Normalized to a mean of 1 inside each (PA cell, count) sub-cell
  (rule 5): it shifts which pitch at a count, and the pool's own outcome mix at
  high pitch counts does the rest. Live inputs exist:
  `state.pitcher_pitch_count` and `times_through_order(state.pitcher_bf[...])`.
* **Code.** A per-(hand, pitch_count, tto) factor is NOT cacheable the way the
  receiving factor is (the count changes every pitch), so compute it on the
  cell rows inside `new_plate_appearance` — cheap after SIM-467 (~5k rows). It
  joins the SIM-455 PA key (the count changes per PA; a PA at pitch 95 and a
  PA at pitch 20 differ). Without SIM-467 the same factor costs a full-pool
  pass per PA; this is why 465's consumer waits for phase 1.
* **Fit.** The probe conditions on the live pitcher's pitch-count band
  (0-25 / 26-50 / 51-75 / 76-100 / 100+) and TTO (1/2/3+): the sim's K, BB and
  in-play rates per band versus the pool's own conditional rates. The manager
  pull model (SIM-434) already reads fatigue on the DECISION side; this is the
  OUTCOME side, and the two are independent.

### 8.3 SIM-461 — batter hand as a weight, not a partition (conditional)

* **The evidence gate.** The point of SIM-461 is cell thickness. After phases
  1 and 3 the lane reports the draw-weighted widening share at the chosen
  `MIN_CELL`. If level-1+ draws are under ~5%, SIM-461 has no case and closes
  on that evidence ("each part individually closable"). If the share is
  material, build it.
* **Design (no rebuild).** Keep the per-hand pool files. `hand_off_weight`
  (`SIM_HAND_OFF_WEIGHT`, 0.0 = today's partition exactly — no rows appended,
  no multiplication runs). When > 0, each count sub-cell appends the
  OPPOSITE-hand pool's same-cell rows at weight × `hand_off_weight`.
  `new_half_inning` then builds `base` for both hands; `f_batter` already
  scores any batter row (the batter embedding carries the platoon splits, so a
  left-handed batter's affinity to right-handed rows is low but real — that is
  what the ticket relies on).
* **Fit.** The probe conditions on the live batter's stand: the sim's outcome
  mix per stand versus the pool's own per-stand mix; the weight is the largest
  value that keeps both stands inside the floors. The risk the ticket names (a
  left-handed batter drawing a right-handed play) is exactly what the probe
  measures.
