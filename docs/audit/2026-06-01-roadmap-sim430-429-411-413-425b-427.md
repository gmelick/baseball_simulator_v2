## SIM-430 — full-pool `/simulate` throughput (fan-out / OOM)

### DONE this session — the per-worker `pitcher_sim` dict OOM driver is eliminated
**Root cause (measured, corrects the design doc):** the OOM was NOT the object-dtype
`outcome_type`/`event` arrays (~15 MB). It was `EngineArtifacts.pitcher_sim`, a
dict-of-dicts (1677 outer × ~3574 inner = 6.0M `{str:float}` entries) costing **~2.0 GB
resident per process** and NOT shareable through `multiprocessing.shared_memory`, so
every worker held a full private copy.

**Fix (shipped):** `build_pitcher_sim_matrix` now also writes a dense
`(n_prof × n_prof)` float32 `pitcher_sim_matrix` (1677² = **11.2 MB**, 60.3% nonzero)
into `pitcher_sim.npz`; `EngineArtifacts.load` reads it and **skips the ~2 GB dict
parse** entirely (dict kept only as a legacy fallback); it rides the existing SIM-403b
shared-memory seam (`extract_shared_arrays`/`attach_shared_views` → `pitcher_sim.matrix`)
so all workers attach ONE read-only view; `FullPoolSampler._f_pitcher` reads a
contiguous row instead of scattering the dict — **byte-identical** draws (8 unit tests,
incl. a full draw-sequence equivalence).

**Live-verified:** an isolated worker-path load dropped from **2364 MB → 367 MB** with
`len(pitcher_sim) == 0` (dict skipped) and the 11.2 MB matrix present; the serving
parent dropped from ~2.4 GB → **270 MB**; boot now publishes **42** shared arrays
(176.9 MB, +1/+11 MB = the matrix). The live `/data/.../pitcher_sim.npz` was densified
in-place (minutes, no engine re-run) and the app restarted onto the matrix path.

### STILL OPEN — the SLA / worker-scaling half, with a NEW precise blocker
Raising `SIM_RUNNER_WORKERS` is still not safe on this host. Live measurement of the
prewarmed ProcessPool worker showed **~6.4 GB private-anon** RSS (two ~1.5 GB arenas),
which is **NOT reproduced by any isolated path**: load = 367 MB, `warm_worker_cache`
in-process = 760 MB, a spawn-child through the full warm path = 467 MB, `_pool_meta` ≈
80 MB. So a *fresh* worker's true footprint is ~470 MB (scaling SHOULD work), but the
live pool worker accumulates ~6 GB through the **shared-views warm path** that static
analysis + isolated execution can't reproduce. The dict was **necessary but not
sufficient.** Next step (needs a dedicated, non-shared host — this box also runs other
tenants): instrument the actual pool worker (`tracemalloc`/`py-spy` from inside
`_prewarm_worker`, or arena analysis via `MALLOC_ARENA_MAX=2`) to find the 6 GB
private-anon source; only then raise workers + hard-gate the n=100 < 30 s SLA.
`SIM_RUNNER_WORKERS` left at **1** (unchanged).

## SIM-429 — calibration quality (partially implementable now)

**(1) Pitcher K/BB PMF over-prediction — root cause found, fix is code-only.** The
SIM-432 validate run found K@5.5 ECE 0.52 (pred_over 0.86 vs obs 0.35), BB@1.5 ECE 0.39,
PMF coverage K 0.41 / BB 0.60 (too narrow). NOT a PMF-builder bug — `prop_distributions`
builds them correctly. The cause: **the starter is never pulled** in production —
`production_machine_factory` builds `StateMachine` with `manager=None`, so
`_maybe_pull_starter` early-returns and one pitcher accrues ~38 BF / ~9 IP every game
(K mean ~2×, tiny variance). This is the SAME root as SIM-427 + a latent bug
(`GameState.pitcher_pitch_count` is **never incremented** in `step_pitch`, so the pull
gate can't fire even when wired). Fix (now): increment the pitch count + wire a default
manager with a generic bullpen into `production_machine_factory` so the starter is
pulled at a realistic workload. **Risk:** changes every game's distribution (W/L/S, ER,
win-prob) → regenerate regression golden fixtures + validate with `sim_stats.py` at
≥400 sims/game; gate behind `SIM_MANAGER=1` (mirror `SIM_FULL_POOL`).

**(2) Runs ~10-12% low — per-channel tuning (now, but iterative).** NOT the global
`SIM_RUN_CALIB` (intentionally neutral). Levers: `_EXTRA_ADVANCE_P` (sim_loop.py:1328-32),
ground-out/fly-out scoring rates, and stronger RISP conditioning in
`FullPoolSampler.battedball_new_pa` (currently soft, `sit_sigma=2.0`). Requires measured
sweeps at ≥400 sims/game reading the per-channel/RISP breakouts — not a one-shot diff.

**(3) Fuller win-prob curve — throughput-gated (SIM-430).** `validate_props` replays N
iters/game serially at ~2.2 s/iter (1 worker). A full-season fit (~2,470 games × 50 ≈
75 h) is impractical until SIM-430's fan-out lands. Interim: a bounded ~600-game/30-iter
overnight fit (~11 h) is runnable today via `--write-calibration`.

**(4) CLV backtest — BLOCKED (no odds).** `raw.game_odds` and `raw.prop_odds` are **empty**
(0 rows). Only `MockOddsAPI` + the live BettingPros provider (current/opening lines, no
historical-closing backfill) exist. A real CLV backtest needs entry+closing lines for
completed games → external historical-odds feed OR forward-capture closing lines on
upcoming games (SIM-340 marking). Only a synthetic-line smoke is possible now.

## SIM-411 + SIM-413 + SIM-425b — one cheap rebuild unblocks all three

All three need per-row `venue_id` / `p_throws` / fielder identity in the batted-ball
artifact — a **minutes**-scale rebuild (NOT the 5.7 h profile recompute): `sim.outcome_pool`
already JOINs `raw.pitches` (which has all three) and the BB artifact uses only a 3-season
recency window (~261K rows). Steps: (a) DuckDB migration adding `venue_id` +
`fielder_player_id` to `sim.outcome_pool` (+ version bump 11→12, + 02_duckdb_schema.sql,
+ `_delete_seasons` enrolment); (b) extend `_build_outcome_pool` SELECT; (c) widen
`build_battedball_pool_artifact` COPY + `BattedBallPool` dataclass/loader; (d) fix the
`fielder_emb` key to `player_id:position:season` (currently 11346 rows collapse to 5336
keys — last-wins). Consumers: SIM-411 park run-multiplier on `state.park` (read
`derived.park_factors` `factor_type='R'`/`regressed_factor`; apply RELATIVE to avoid
double-counting the park-influenced pool + reconcile with the SIM-412 flat home bias);
SIM-413 same/opposite-hand soft reweight in `battedball_new_pa`; SIM-425b out↔hit↔error
nudge in `_full_pool_fielding` from `fielder_emb` OAA/error_rate. **Implementable now
(unit-testable, no rebuild):** the migration, the `_build_outcome_pool` SQL, the builder
+ loader changes, the fielder-key fix, and the three consumer helpers behind synthetic
fixtures. **Wiring to confirm:** `venue_id` + the per-position fielder map must reach the
worker `GameState` (today only the catcher is on `GameState`; `state.park` is a dead
field never set by `build_game_state`). **Regression:** the fielder-key change is an
engine-drift event → regen golden fixtures intentionally.

## SIM-427 — engine-backed manager (bullpen roster)

Build `derived.team_bullpen_roster` (one row per team/season/pitcher) from `raw.pitches`
(starter = the min-(at_bat, pitch) arm per game/fielding-team; GS counts; reliever
leverage rank), then fill the six manager USAGE columns (currently `NULL::FLOAT`,
gated) and feed a per-team reliever list into `ManagerContext.bullpen_available`.
**Code-only now:** the `team_bullpen_roster` SQL + migration (+ version bump — **note: this
collides with SIM-411's 0012; renumber one to 0013**) + the `_compute_manager_profiles`
USAGE rewrite + the `simulate_game`/`production_factory` `manager=`/`bench=`/`bullpen=`
passthrough + **the `pitcher_pitch_count`-never-incremented fix** (shared with SIM-429
sub-1). **Blocked:** populating real values needs the profile recompute (~5.7 h) + an
engine-artifact rebuild so a pulled reliever carries its true similarity profile (else it
degrades to a league-flat draw — still valid). Today manager hooks are a **total no-op**
in production (`manager is None`), so wiring them on turns on pinch-hit/steal/sac-bunt
simultaneously → gate behind `SIM_MANAGER=1` and validate each effect independently.
