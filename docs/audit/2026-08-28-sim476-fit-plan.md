certified baseline is the 2026-08-20 lane-2 scoreboard (BACKLOG banner +
`docs/audit/2026-08-20-sim429-514-diagnosis-results.md`): all eleven pool

off. A knob whose channel is green is not a fit target** — moving it is
relitigating a certified result.

## The fit principle: conditional frequencies, not game totals

The 2026-08-20 grading ruling gives the objective function. The sim is a
similarity-weighted sampler of the pool; a kernel is CORRECT when the sim's
frequencies, CONDITIONED on the thing the kernel reads, match the pool's own
conditional frequencies. Fit at the per-opportunity level (cheap, high power);
verify at the game level (expensive, once). Never fit a bandwidth against a
per-team-game season total — that is how the era gap contaminated SB/CS.

## Part 1 — the steal attempt weighting (the asserted red; do this first)

**The defect.** Attempts per opportunity: 2B 0.0184 vs the pool's own 0.0217
(−15%); 3B 0.0042 vs 0.0043 (clean). The safe split is calibrated (0.8043 vs
0.7951). So the ensemble under-SELECTS attempted rows at 2B specifically.

**Prior evidence (do not re-measure):** SIM-507's single-factor ablations
(`SIM_STEAL_ABLATE_{CATCHER,RUNNER,PITCHER}`) showed no single kernel moves
attempt volume more than ±3%, and the runner-only draw reads the split high
(80.9%) with catcher+pitcher pulling it back. Conclusion: the −15% lives in
the JOINT weighting, so fit the bandwidths together, not by one-at-a-time
ablation.

**PRIME SUSPECT (found by inspection 2026-08-28, arithmetic matches the
measurement): the manager AGGRESSION multiplier double-counts leverage.**
`_steal_opportunity_draw` (sim_loop.py:3883-3894) computes

    li_scale   = 0.5 + 0.5 * min(LI / 1.5, 2.0)
    aggression = clamp((tendency / 0.08) * li_scale, 0.05, 4.0)

and `steal_draw` multiplies the weight of ATTEMPTED rows by it. Under the
league-flat SIM-427 default profile, `tendency / 0.08 = 1.0` exactly, so the
whole term reduces to the bare `li_scale` — a hand-set leverage formula (the
same class the SIM-515 IBB fix retired). It equals 1.0 only at LI = 1.5
("high leverage"); an ordinary runner-on-1B pitch sits at LI ~0.7-1.1, so
aggression runs ~0.73-0.87. For a rare event, weighting attempted rows by w
scales the drawn attempt probability to ~w·p — a **13-27% suppression,
centred on the measured −15%**. It also explains every side fact: 3B attempts
are clean because runner-on-2B pitches carry higher LI (leverage rises with
runners on — pinned by the LI unit tests), pushing their aggression to ~1;
the safe split is untouched because the weight multiplies safe and caught
attempted rows alike; and no SIM-507 kernel ablation found it because none of
the three ablation seams touches the aggression term. The double-count: the
pool draw ALREADY conditions on (outs, balls, strikes) hard and score-diff
softly — the ingredients of leverage — so the cell's real attempt rate
already embodies how often real runners went at that leverage. Multiplying by
a leverage-shaped weight applies the discount a second time.

**Step 0 (before any sigma fitting) — the neutral-aggression A/B.** One
12×400 run with aggression forced to 1.0 under the league-flat profile
(either delete the `li_scale` term, or gate it to fire only when a REAL
per-manager tendency differs from the league mean — the SIM-427 wiring).
Prediction: 2B attempts/opportunity recovers most of the −15% and 3B moves
little. If confirmed, the fix is the deletion, not a bandwidth: per-manager
aggression returns as `tendency / league_mean` alone (no leverage factor)
when SIM-427's real profiles land. The per-cell localization (step 1) then
re-measures whatever residual remains before touching `steal_sigma`.

**OWNER DECISION (2026-08-28): keep the manager term as a WEIGHT, delete the
leverage factor.** The recommendation adopted: aggression becomes the
per-manager ratio alone (measured manager attempts/opportunity ÷ league
attempts/opportunity when SIM-427's real profiles land; ≡1.0 under today's
flat profile), and the `li_scale` formula is deleted. If the per-cell
localization later shows a LATE-GAME residual, the honest fix is data
conditioning — an inning/is-late soft kernel on the steal draw — never a
formula.

**Two adjacent findings from the same inspection (2026-08-28):**
  * **The hit-and-run is a booby trap.** `hit_and_run_signalled`'s ONLY
    consumer is the pre-pitch hook's early return, which SKIPS the steal draw
    on that pitch — the advertised runner-go and contact bias are wired
    nowhere. It never fires today (the production profile carries no
    `hit_and_run_rate_per_opportunity`, so the tendency reads 0.0), but the
    moment SIM-427 profiles include the rate it becomes a pure steal
    suppressor. Retire it or rebuild it as a pool decision WITH SIM-427 —
    never let it go live as-is. `pitch_out` and `sac_bunt` are fully dead
    (signals set / decisions logged, nothing consumes them) and `pinch_hit`
    is a no-op without a bench; all four are SIM-427-scope, not SIM-476.
  * **`platoon_off_weight` (0.6, SIM-413, ON in production) is the one other
    hand-SET value on a live draw seam.** The marginal pool bands cannot see
    a wrong platoon value — marginals integrate the matchup out — so part 3
    gains a CONDITIONAL check: same-hand vs opposite-hand batted-ball event
    mix, sim vs the pool's own, before deciding whether 0.6 needs a fit.

**Step 1 — localize before fitting.** Extend the steal instrumentation
(`scripts/sim514_decomposition.py` is the base; wrap per-GAME machines via
`machine._steal_opportunity_draw`, never the cached sampler — the recorded
trap) to report sim attempts/opportunity PER CELL (target × outs × count
class) against the pool's own per-cell rates. Three possible shapes:
  * uniform −15% across cells → a temperature problem (the kernels concentrate
    weight on non-attempted rows everywhere) → step 2;
  * concentrated in specific cells (e.g. two-strike counts) → a cell-level
    defect, possibly data — file it before fitting anything;
  * a runner-mix effect (elite stealers' cells fine, average runners short) →
    the runner kernel bandwidth specifically.

**Step 2 — the fit.** Objective: sum over cells of
|sim_att/opp − pool_att/opp| weighted by opportunity count, plus the safe-split
deviation as a constraint (it is green — the fit must not break it).
Parameters: (`steal_sigma`, `steal_score_sigma`) — a 2-D grid (5×5 around the
current values, log-spaced) is affordable because the objective needs only
~400×12 instrumented sims per point IF measured per opportunity (~1.3M
opportunities per run → per-cell SEs under 1%). Use ONE instrumented harness
run per grid point; the harness prints the objective. Train/test: fit the
objective on odd-seed halves, confirm on even seeds (season-split does not
apply to a sampler-fidelity objective; seed-split guards the same overfit).

**Step 3 — certify and re-reference.** Land the fitted values as the new
defaults (document the fit run in the constants' comments). Re-run the 12×500
lane. Then add the steal channels to `bands.POOL_REFERENCES` —
`STEAL_ATT_OPP_2B`, `STEAL_ATT_OPP_3B`, `STEAL_SAFE_2B` — with centres from
the pool (the census pattern) and probes in the lane conftest (the
`pool_counts` pattern; count per target base). That moves SB/CS off the 2025
era reference, the same supersession the other frequency channels got, and
retires the last two game-graded frequency asserts.

## Part 2 — `home_off_weight` (the home_win_pct lever)

**The cheap objective the pool now affords:** the pool carries `bat_home`
(migration 0019), so the reference is the pool's OWN home-vs-away conditional
event mix (per-BIP event rates for bat_home=1 vs bat_home=0 rows). Fit
`home_off_weight` so the sim's home-half vs away-half per-BIP mix reproduces
the pool's differential. This is a per-opportunity fit — thousands of sims,
not tens of thousands of games. A 1-D golden-section over [0.7, 1.0] with
~6 instrumented points (≥400×12 each) resolves it.

**Then verify downstream, once:** the 13,365-decisive-game home_win_pct lane
(~8-16 h, its OWN run — never the 12×500). Expect movement from 0.4848 toward
the 0.5428 centre; the first A/B smoke (weight 0.7) moved 0.511 → 0.539 at
noise-level n, so the direction is already right. If the fitted weight passes
the conditional-frequency objective but home_win_pct still reads low at full
power, the residual is NOT this knob — do not crank it past the
conditional-frequency optimum (that is the hand-tuning anti-pattern); file
the residual with its measurement.

## Part 3 — `park_sigma` and `fielder_sigma` (same pattern, one at a time)

* **`park_sigma`**: objective = sim per-BIP event mix conditional on the live
  venue's factor class (low/mid/high park terciles across the 12 lane games)
  vs the pool's own per-venue-class mix. Fit the Gaussian bandwidth over
  [0.02, 0.15]. The deleted-flip instruction fires here: when the fitted
  kernel is enabled in production, DELETE `_apply_park_factor` and its
  constants (the legacy flip; inert on the transition path, flag-off in CI).
* **`fielder_sigma`**: objective = sim out-vs-hit rate on fieldable balls
  conditional on the live defender's OAA tier vs the pool's conditional rates.
  Same 1-D fit. Same deletion instruction for `_fielder_rbf_nudge` on enable.
  Consider widening `_FIELDER_BB_FEATURES` toward the arm features only if the
  OAA-only fit leaves a measured conditional gap.

## Validation protocol (the standing bar, unchanged)

One flag at a time; each fit run at ≥400×≥12 instrumented sims; byte-identical
with the knob at its off value (the CDF-equality tests already pin this); the
12×500 pool-band lane after each landing; golden-fixture regen only if a
DEFAULT changes flag-on production behavior (the unit conftest pins everything
off, so CI baselines never move); the home_win_pct full-power lane LAST, once,
after parts 1-3 land. Update the docker-compose `app` env with the fitted
values in the same commit that lands each default.

## Order and expected cost

1. Steal localization run (~1.5 h) → the fit grid (~8-10 h of detached lane
   time, parallelizable two containers at a time) → lane + band re-reference.
2. `home_off_weight` fit (~4 h) → 12×500 lane (~4.5 h).
3. `park_sigma`, then `fielder_sigma` (each ~4 h fit + shared final lane).
4. The home_win_pct full-power lane (~8-16 h, weekend job).
5. After all of it: `make calibrate` + `make validate-props` (the K-prop ECE
   0.109 target) and the `scripts/clv_backtest.py` re-measure — the SIM-429
   closers, on a fully fitted engine.

Everything above is measurement-first: every fit has a pre-registered
objective the pool itself defines, and every landing is certified by the same
lane that caught the IBB label defect.
