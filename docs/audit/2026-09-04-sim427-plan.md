# SIM-427 — real manager profiles + the dead-signal cleanup: the build plan (2026-09-04)

**Status: PLAN. Nothing in this document is built.** It scopes the open SIM-427 row
(`BACKLOG.md`, the 2026-08-29 consolidated board: "real manager profiles + the
dead-signal cleanup: pitch_out / sac_bunt / the hit-and-run trap / pinch-hit"),
names every file the work touches, and lists what changes downstream. §8 lists
the four decisions the owner must make before part (c) starts.

**The headline.** The manager engine's DATA side is done (the 2026-06-03
capstone: all 17 tendency columns computed for every manager-season, the 7th
USAGE feature wired and calibrated). The SIMULATOR side never consumed it. Every
game today runs one league-flat hand-set profile for BOTH dugouts and a synthetic
six-arm bullpen of negative player ids per side. The pull decision is a formula.
Wiring the real profiles into those formulas is NOT a drop-in: the measured
league rates sit far from the constants the formulas were tuned to (§3), so a
plug-in would pull every starter at 75 pitches and cut steal attempts ~23%. The
plan therefore rebuilds the pull as a pool draw (the SIM-468 / SIM-515 pattern)
and treats the real profiles as draw WEIGHTS — the 2026-08-10 architecture rule.

## 2. What "real manager profiles" must deliver

1. Each dugout runs its OWN manager's measured tendencies, per season.
2. Real relievers replace the synthetic pen: real ids (so the pitcher engine
   scores them), real throwing hands, real rest, real availability.
3. The pull and the reliever choice obey the architecture rule: a
   similarity-weighted draw from a hard-filtered pool, and the drawn row IS the
   play.
4. The steal weight becomes the manager's measured ratio to a MEASURED league mean.
5. The dead signals go, so the real profile can never trip the hit-and-run trap.

## 4. The design: draws, not plug-ins

**Rejected: the plug-in (the SIM-434 follow-on as filed).** Passing the real
per-team dicts into the existing hooks keeps three formulas live and forces a
re-tune of their constants to the measured scale. That is hand-tuning, which the
2026-08-10 rule forbids, and §3 shows the constants would have to move 2.5×
(pull) and 1.36× (steal) just to stand still.

**Adopted: the pull becomes a draw from a pitching-change OPPORTUNITY pool.**
The SIM-468 steal pool is the template: one row per plate-appearance boundary
while a pitcher is on the mound, changed or not (the denominator the formula
never had). Columns: season, game_pk, fielding `manager_id`, `pitcher_id`,
`is_starter` (stint rank 1 — the `staff` CTE at `player_profile_computor.py:3029`
already computes stints), `pitch_count` so far, `batters_faced` (times through
the order), inning, outs, `runners_state`, `score_diff` (fielding − batting),
`changed` (BOOL), and the incoming arm's `incoming_pitcher_id`, `incoming_hand`,
`incoming_role_rank` (the arm's team-season rank by high-leverage share — the
`hi_lev` CTE's ingredients). Recency weight as every pool.

The draw hard-filters the cell (`is_starter`, pitch-count bucket of 10, TTO) and
weights softly by: the situation kernel (inning, score, base-out — the existing
`sit_sigma` machinery), the CURRENT pitcher's similarity row (`pitcher_sim_matrix`
— a tired ace and a fifth starter draw different rows), and a NEW manager kernel:
an RBF over the z-scored USAGE vector between the live manager and the row's
manager. The artifact bundle already exports that embedding
(`engine_artifacts.py:415-425`, `_ACTOR_TABLES["manager"]`); nothing consumes it
today. Env `SIM_MANAGER_KERNEL_SIGMA`, 0 = flat = byte-identical to a no-manager
weighting; fitted per the SIM-476 method (§5c). The drawn row's `changed` flag IS
the decision. MLB sanity: ~4.2 pitchers per team-game means ~3.2 changes over ~38
boundaries, ~8% per boundary — the pool's own rate, no constant.

**The reliever choice reads the drawn row.** The row says which KIND of arm
entered (`incoming_role_rank`, `incoming_hand`); the live pen (real, ordered by
the same rank) supplies the arm of that rank, nearest available; a hand mismatch
prefers the nearest-rank arm of the drawn hand. That is a mapping of the drawn
row onto the roster, not a scoring formula. `score_reliever`, `platoon_factor`,
`tto_effectiveness`, `pitcher_fatigue` and the 75/110 constants are deleted with
their tests when the draw lands.

**Steal aggression** stays the SIM-476 form (the manager ratio, no leverage
term) with a MEASURED denominator: the new manager row in
`derived.league_averages` (per season). The certified `STEAL_ATT_OPP_2B` band is
the regression guard.

**IBB per-manager weight: DEFERRED.** The profile has no IBB column; adding one
means a schema change plus a manager-profile recompute plus an engine feature
count change (fixtures + calibration). File it as its own row when SIM-427
closes; the SIM-515 cell draw stays as is.

**Pinch-hit, sac bunt, pitch-out, hit-and-run: DELETED, not rebuilt here.** Each
would need its own opportunity pool and a bench source. Under the rule they are
OFF until a weight lands, and OFF code that reads a real profile is a trap
(hit-and-run) or noise (sac-bunt records in `manager_decisions`). The bench draw
is a SIM-518-class enrichment (§9).

## 6. Downstream impacts (the census)

**Simulation output.** Starter-IP and reliever-share distributions change (the
whole point). K/PA and BB/PA marginals move a little: relievers strike out more.
The pool bands are per-opportunity and certified at ±2-3%, so the lane must
re-run — do not assume they hold.

**Props + calibration.** Pitcher K / BB / outs PMFs shift for starters; real
per-reliever prop rows appear for the first time. The SIM-429 K-prop refit and

**Bands and harnesses.** Two new bands (5c-6); `PRODUCTION_FLAGS` gains

**Data operations.** Two data runs with the app stopped (5a-3); the 2026

**Tests deleted / rewritten.** ~1,250 lines across `test_sim434_manager_model.py`,
`test_baseball_analyst_sim323.py`, `test_baseball_analyst_sim349.py`; the
