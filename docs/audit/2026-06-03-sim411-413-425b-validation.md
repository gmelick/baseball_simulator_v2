## 3. The defense-map bug (found + fixed)

The fielder config was first **byte-identical to baseline (0 flips / 10,950 calls)**. Root cause:
`raw.game_lineups.position_code` stores canonical **names** (`'SS'`,`'C'`,`'1B'`… across all 543K
rows), but `build_team_defense_map` routed them through the **number-keyed** `POSITION_CODE_TO_NAME`,
so `get('SS')→None` and only the explicitly-added pitcher survived. The defense map was `{'P':…}`.
This left **SIM-425b fielder-RBF AND SIM-428 catcher framing silently inert in production** (SIM-428
was marked DONE but never had a resolvable catcher on real data).

**Fix** (`simulation/lineup_resolver.py`): accept a canonical name directly, numeric fallback retained.
Unit fixtures use numeric codes (unaffected → no fixture drift); a name-format regression-guard test
was added. Post-fix the diagnostic shows all 9 positions resolve and 219/284 calls eligible.

## 4. Adversarial verification — verdicts (`wf_5267ae46-cf5`)

- **engagement-integrity → REFUTED (medium).** Fielder/park counters are genuine *effect* counters
  (140/570/179 flips → those two engage). But (a) **"flag-off byte-identical" is FALSE at the game
  level**: the defense-map fix activates always-on SIM-428 framing, which consumes an `rng.random()`
  before the flip check → reorders the RNG stream → the all-flags-off baseline shifts 8.85→8.65 and
  seeded games no longer reproduce pre-fix output. The three *named* flags ARE byte-identical off
  (proven by the pre-fix fielder==baseline result). (b) `platoon_engaged` is a *call* counter, not an
  effect counter. (c) the engine regression gate tests `.query()`, not `simulate_game`, so "green" is
  **not** evidence of game-level byte-identity.
- **park-calibration → UNCERTAIN (medium).** Direction correct. Hitter side (+1.86 both-teams @1.20)
  plausible but low vs MLB ~+2–3. **Pitcher side (-0.23) is ~5–8× too weak** — structural: the
  single→out branch draws from a ~3× smaller pool than out→single. **`_PARK_FACTOR_STRENGTH=0.5` was
  never exercised** — at |factor−1|≥0.16 the probability is cap-bound (0.08), so the 1.20/0.80 sweep
  tells us nothing about the strength knob.
- **fielder-calibration → UNCERTAIN (medium).** Code + sign correct. But the +1.19 ΔH **exceeds the
  mechanical ceiling** (0.7 flips/game) → the configs weren't seed-paired → deltas are noise. And the
  `q_pool` game-season lookup was a **survivorship filter** (only pool fielders qualifying in the game
  season scored) biasing toward more hits.
- **sim428-sideeffect-risk → UNCERTAIN (medium).** Map-building logic verified correct (DH/double-
  switch/pitcher handled). Other consumers safe (matchup provider doesn't read the map; park reads
  `state.park_run_factor`; field-graphic handles empty/populated). The real risk is the framing
  activation's RNG-stream/reproducibility change + a now-populated `/state` 9-fielder field graphic.

**Synthesis: `safe_to_land = true`** — land the defense-map fix + the three gated-OFF flags; the only
flag-off behaviour delta is the SIM-428 framing activation, which is correct (SIM-428 as designed) but
must be documented.

## 5. Fixes applied from the review (this commit)

1. **`SIM_FRAMING` gate (default ON)** — makes the SIM-428 framing activation explicit/auditable;
   `SIM_FRAMING=0` restores the pre-fix catcher-inert path (no rng draw) for a strict byte-identical /
   seeded-reproducibility mode. Default ON preserves SIM-428's intended behaviour. +3 tests (gate
   on/off + default).
2. **Fielder `q_pool` season fix** — `last_battedball_fielder()` now returns the pool row's own season;
   `_fielder_rbf_nudge` scores the pool fielder at their **contemporaneous** season (the live defender
   stays at the game season), removing the survivorship filter that capped coverage at 77% and biased
   toward hits.
