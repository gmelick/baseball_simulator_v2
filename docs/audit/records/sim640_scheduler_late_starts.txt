== The scheduled jobs start late after a pause of the laptop: the evidence, 2026-10-18 to 2026-11-12 (SIM-640) ==

Every time is UTC. The laptop's own clock read UTC-4 until 2026-11-01 06:00 UTC, and UTC-5 after.
A pause is a standby or a hibernate of the laptop. Windows' Sleep command starts a standby here:
powercfg /a lists Standby (S0 Low Power Idle), Hibernate and Fast Startup. Modern Standby is that
standby: the screen goes off and the laptop idles. Fast Startup makes a Start-menu shut down save
the system to disk, so the next start is a resume. Docker's virtual machine (VM) can stand still
during a pause.

the cron run loop, robfig/cron v1.2.0 cron.go, Cron.run (lines 170-202):
  it arms ONE timer for the earliest job: time.NewTimer(c.entries[0].Next.Sub(now))
  a Go timer counts the monotonic clock: the clock that counts only the time that the VM runs
  on a fire: now = now.In(c.location) (In drops the monotonic reading), then every job whose
  Next is not after now runs; each Next becomes Schedule.Next(now); the loop re-sorts and re-arms
  at the start, each Next = Schedule.Next(c.now()): a job whose time passed before a start never runs
the VM's lost running time = (now - the VM's boot) - /proc/uptime, read in the scheduler container;
  the VM's boot = the scheduler's PID 1 StartedAt (docker inspect) - /proc/1/stat field 22 / 100
  (CLK_TCK is 100). The figure adds up every pause since the boot: compare a reading before a
  pause with one after it.
the heartbeat (the proposed fix): a job that does nothing every five minutes, so the scheduler
  wakes and starts each overdue job.
